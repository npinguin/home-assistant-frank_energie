## Contract and data-quality invariants

1. Only explicitly supported enum states become HA values; source `None`, empty, `unknown`, or unsupported state yields no invented enum option.
2. Known `MODEL`, `SMR3`, `SMR1` remain observable (case-normalized and translated).
3. Existing meter sensor prefers electricity if available and exposes `meter_types_by_segment` for both electricity and gas. Preserve device/entity identities.
4. Contract price resolution `None` is not the same thing as *effective* public price feed resolution `PT15M`. Contract mutability remains sourced from the API; no invented control.
5. Public market prices stay on the anonymous API client; account-specific prices use authenticated queries.
6. Device software version equals installed integration manifest version, without copying a second hardcoded value.
