# Frank Energie 2026.11.1.4 — HACS TEST: service refresh and truthful source timing

**Controlled HACS prerelease for real Home Assistant acceptance.** Source is
the existing Draft PR #18 on `fix/be-price-provenance-truth`. No stable promotion
or merge to `main` is authorized by this TEST publication.

## Functional changes since installed 2026.11.1.3

- Service-level **Refresh** controls for the existing Prices, Gasprices,
  Costs, Usage, User and present connected-service devices. Requests are routed
  to the owning coordinator. Costs and Usage intentionally share Statistics;
  Prices and Gasprices share Prices. There is **no independent API polling per
  HA device**. The previous Prices button keeps its stable identity.
- **Refresh interval** diagnostic sensor for each service, in minutes, sourced
  from that coordinator's actual (possibly dynamic) polling interval.
- **Last API check** diagnostic timestamp sourced solely from a real
  observed GraphQL provider call since startup; no HA Activity timestamps are
  misrepresented as provider checks.
- Additional attributes show last successful API *response*, latest outcome,
  and **estimated** next refresh. This estimate is not HA's internal scheduling
  deadline or proof of a complete meter reading. Requests may be skipped during
  00:00–01:00 UTC maintenance. Price slot transitions need no new API call.
- Per-service timing appears in anonymized diagnostics under
  `coordinator_evidence.refresh_schedule`.
- Previous pending code now included in this test candidate: price cache
  startup liveness, valid-today fetch provenance, no duplicated price API
  polling from the time-slot clock, honest recovery outcomes and the
  November/month rollover check that withholds previous-month financial
  totals from current-month sensors.

## Known limitations / release gates

- This prerelease has **no live BE HA/HACS acceptance yet**. A synthetic green
  pytest run cannot establish real Recorder, device placement or rollback.
- The authenticated Belgian `MODEL` contract shows missing historical gas
  usage, and the vendor can exclude gas from `MonthInsights`; financial
  components must remain source-quality-marked rather than fabricated.
- A GraphQL error or no current-month publication is not a valid monthly
  cost; previous-month amounts may not be shown as current-month actuals.
- API requests may be more frequent than the displayed coordinator interval
  during explicit recovery, setup or manual actions, while finance source
  snapshots may be cached. The next-refresh time is deliberately an estimate.
- The current provider observer stores only the last 96 safe events in memory.
  Older last-check history is unavailable after restart/retention expiry.
- Provider settlement lines, invoices and gas completeness remain unverified
  for a stable, all-in Belgian monthly cost result.
