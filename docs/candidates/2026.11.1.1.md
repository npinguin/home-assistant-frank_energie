# Frank Energie 2026.11.1.1 — consolidated HACS TEST

**Status: controlled HACS pre-release only. Not stable.**

Source: the single consolidated release train on Draft PR #18, based on
immutable `v2026.10.31.2` with live Belgian diagnostics follow-up and
CI governance from the earlier branches. This test candidate does **not**
merge the release PR or overwrite prior release assets.

## Scope to verify in actual Home Assistant

1. **Selected delivery site:** the settings coordinator owns the list of
   customer sites. The price coordinator now derives actual electricity/gas
   subscription flags from the selected site, rather than leaving its own
   default `False` flags untouched. Multiple delivery sites must not leak
   one site's subscription into another.
2. **Price provenance:** distinguish selected `customer`, `public`,
   `public_fallback`, `mixed`, `cached_fallback`, `not_available`
   based on actual nonempty selected price slots, not network success.
   The public anonymous feed remains separate from the authenticated
   customer feed. A public market spot value is **not** evidence of the
   actual billed price of a Belgian `MODEL` variable contract.
3. **Contract diagnostics:** `Connection` dataclass fields in the pinned
   Python API client are read safely, not discarded by a dictionary-only
   reader. Expected `contract_capabilities.segments` entries include
   applicable `electricity` / `gas`, with opaque provider meter code,
   contract type and boolean last-reading presence. No connection IDs,
   EANs, addresses, prices or amounts may be serialized.
4. **Price-day coverage:** `price_coverage.*.slots_by_local_day` reports
   sanitized selected slot counts by Europe/Brussels local day. This is a
   diagnostic count only; it **does not prove full interval coverage**.
   `has_active_today_prices` reports the actual static day cache separately
   from the legacy `has_cached_today` flag.
5. **Existing functions:** config entry, entity IDs, device registry,
   Recorder history, authenticated/public GraphQL behavior and other
   integration features must not regress. No new API call is introduced
   by these diagnostics changes.
6. **CI governance:** obsolete broken Pages workflow retired; PR/issue
   labelers do not run PR-only APIs on issue events.

## How to install the candidate and collect evidence

1. Back up Home Assistant and the previous Frank Energie integration
   directory, including current configuration entry and entity registry.
   Preserve these; **do not delete/re-add the integration**.
2. In the existing HACS custom repository for the **fork**, select or
   download the published HACS pre-release `v2026.11.1.1`. Ensure the
   release has a real `frank_energie.zip` asset and matching checksum.
   Restart Home Assistant; confirm manifest version `2026.11.1.1`.
3. Wait for the regular price/statistics refresh. Then open **Settings →
   Devices & services → Frank Energie → ⋮ → Download diagnostics**.
   Share the export privately. Do not enable `python_frank_energie: debug`
   because the pinned upstream library can log private account payloads.
4. Validate selected-site electricity/gas enabled flags, MODEL contract
   segment metadata, raw vs parsed vs final price slot outcomes, selected
   day counts, effective resolution and cached-today health.
5. For delayed tomorrow prices, export again after provider publication
   without creating new clients or manual polling. Look at timestamps and
   selected day counts to distinguish 6 gas slots from complete coverage.
6. Check entity/device registry IDs and Recorder history before/after
   upgrade; ensure previously known entities are not recreated.

## Known limitations / stop conditions

- **#11**: pinned `MonthInsights` parser silently converts absent numeric
  amounts to 0.0. Ambiguous zero is conservatively withheld and monthly
  finance defaults **OFF**. Do not infer missing data equals zero or
  enable it as stable invoice accounting before source-contract proof.
- Real Belgian invoice reconciliation, capacity-tariff handling, gas
  meter reading publication and finance history are **not validated**.
- `MODEL` is a variable commercial contract; public spot prices remain
  planning signals, not contract prices.
- The current release candidate does not auto-fix external Frank API
  outages or unknown `SmartHvacStatus` errors.
- No HACS stable promotion or merge to `main` without real installation,
  rollback, Recorder and account-source acceptance.

## Rollback

Restore the **complete** previously installed v2026.10.31.2 integration
directory or re-install that immutable HACS prerelease, then restart HA.
Do not mix files from both versions, delete existing config entries, or
rename entities to work around a failing update. Existing Recorder data
must remain intact. If a rollback fails, collect safe diagnostics before
changing the account config.
