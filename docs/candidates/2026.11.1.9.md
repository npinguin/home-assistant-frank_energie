# Frank Energie 2026.11.1.9 — Belgian monthly source readiness and complete-day gas truth

**Immutable HACS TEST prerelease only. Not stable, not invoice-validated.** Candidate for the **existing Draft PR #18**; supersedes no earlier tag and does not modify `main` or `python-frank-energie==2026.9.20`.

## Changes since immutable v2026.11.1.8

1. **Two optional monthly financial-readiness sensors:** `finance_current_readiness` and `finance_previous_readiness` on the existing Costs service device, only when authenticated `Monthly Finance` is enabled. Readable states: `not_published`, `contract_unverified`, `electricity_missing`, `gas_missing`, `provider_total_missing`, `provider_components_present`. Source quality attributes name the missing provider components without disclosing account identifiers, billing amounts or raw GraphQL errors. `provider_components_present` **does not imply all-in house cost, network/capacity tariff or invoice reconciliation**.
2. **Correct monthly source semantics:** a period-scoped `MonthInsights` full-month forecast can be available before the first meter reading in that calendar month; **actual** and **until-reading** costs continue to require a valid meter date. Raw null versus zero and selected-site gas exclusion guards remain in force.
3. **Transient provider resilience:** last confirmed previous-month `MonthInsights` evidence remains readable if a later refresh fails, strictly scoped to the same selected site and month. Failure does not mark the retry successful; older fetched timestamps remain honest.
4. **Gas forecast honesty:** seven tomorrow gas average/min/max summary readouts require verified full **local calendar-day time interval** coverage. If the provider publishes only six hours, the summary sensors become unavailable; individual future slots remain visible in the existing source series. Works across 23/24/25-hour DST days.
5. **Tests, translations and handover:** deterministic regression tests for source completeness, first meter reading, raw field truth, prior-month cache and site isolation; current/previous readiness labels for `en`, `nl`, `nl-BE`, `fr`. Permanent engineering and lessons-learned entrypoint: [Financial visibility runbook](../engineering/FINANCIAL_VISIBILITY_RUNBOOK.md), also linked from root `AGENTS.md`, Belgian source and Basic consumer contracts.

No new API query, credentials, separate HA integration, Home Assistant unique-ID migration, Recorder backfill, billing engine or optimizer is introduced.
