# Frank Energie 2026.10.31.1 — integrated HACS TEST candidate

**Status:** test candidate only; no target-HA runtime approval, no stable promotion.
**Base:** upstream-synchronized fork `main` (2026-10-30/31). No second integration.
**Pinned client:** `python-frank-energie==2026.9.20`; no unversioned dependencies.

## Included

- Isolated, unauthenticated public `MarketPrices` client. Authenticated account
  queries remain authenticated. Supported PT15M/PT60M resolution and caching
  semantics from synchronized upstream are preserved.
- Account ENUM validation for nullable contract resolution, `MODEL` offer,
  electricity `SMR3` and gas `SMR1`. Existing meter entity identifiers remain
  unchanged; separate segment types appear as attributes.
- Anonymous-to-authenticated reconfigure validates delivery-site selection
  before modifying entry data/options. Wrong credentials or unavailable sites
  must not damage the existing public-only entry.
- Optional `Monthly usage and costs` (default **off**): source-backed
  current/previous calendar-month electricity, gas and feed-in actuals and
  provider-expected values. Separates gas m³ and kWh without synthetic conversion.
  No backfilled Recorder statistics and no fabricated capacity tariff.
- Finance API exception isolation and retry after transient missing historical
  month; previous month cached only on successful source response.
- Privacy-hardening in HA setup, login and options logs. More useful bounded
  per-coordinator diagnostics distinguish price success from missing finance data.

## Evidence from existing HA diagnostics (2026-10-31)

The older installed **2026.10.23.1** ran on HA OS/Core **2026.10.4**,
Python 3.14.9, BE site with confirmed `MODEL`, electricity `SMR3`, gas
`SMR1`, and `active_option: null`.

It reported coordinator success, PT15M effective resolution, no cached today,
cached tomorrow, two empty serialized price lists with 60-minute resolution,
and unavailable day usage, invoices and month summary. This is **not**
proof the new candidate is working: it exposes an observability and
data-availability regression risk that must be tested again after installation.
No original account IDs, site references, tokens, EAN, addresses or invoices
are included in this document or fixtures.

## Known limitations / blocking stable finance release

1. The pinned Python client's `MonthInsights` parser turns absent numeric
   fields into `0.0`. This candidate **withholds all zero-valued month
   actuals** as `zero_unverified_by_client`, including genuine zero.
   Correctness takes priority over a plausible but false finance total.
   Source repair tracked by issue #11.
2. A true month-to-date electricity/gas split, sign, period attribution and
   delayed Belgian gas publication still need an actual redacted provider
   month sample. Tests use synthetic fixtures.
3. A successful price coordinator is not evidence that billing,
   statistics, or tomorrow/today pricing actually have usable values.
4. Third-party `python_frank_energie` has raw monthInsights debug logging
   in pinned versions; **do not enable its debug logger with a real account**
   or share raw logs. The upstream client requires a separate privacy fix.
5. The earlier HACS/GitHub CSP HTTP response-header issue (#6) may block
   downloading before ZIP bytes arrive; a separate documented hotfix is
   available. Do not confuse that with a broken release asset.

## Install / rollback

This GitHub pre-release is distributed as **`frank_energie.zip`** in HACS
zip-release layout (integration files at archive root), plus `SHA256SUMS.txt`.
Check checksum before manual extraction. Back up the existing
`/config/custom_components/frank_energie/` directory and Home Assistant
configuration. Replace the **entire** integration directory and restart HA.
Do not merge loose old and new files.

For rollback, restore the entire previous directory from backup or the known
old test artifact, restart HA, and verify device/entry/entity continuity.
Avoid enabling the monthly opt-in until you deliberately start the experiment.

**This artifact is a controlled test candidate, not production authorization.**
