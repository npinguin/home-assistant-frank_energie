# Frank Energie 2026.11.1.8 — Belgian GraphQL error discovery

**HACS TEST prerelease only, not stable.** Follow-up on existing Draft PR #18, with no rewrite of earlier immutable HACS TEST v2026.11.1.7.

## Change versus 2026.11.1.7

- Provider GraphQL observability recognizes a bounded allowlist of safe error categories: schema validation, non-nullable-field error, missing reading dates, unavailable market prices, unsupported country, invalid input, authentication/authorization, rate limit, provider availability/internal error, and explicit unclassified.
- Where a GraphQL error includes a known top-level field path (e.g. `monthInsights`), diagnostics retains only the whitelisted root; never raw error messages, IDs, tokens, account information, arbitrary extensions, price amounts or query variables. Changes are passive: **zero additional network requests** and no modification to the provider request/response.
- Tests cover error categories, allowed roots, arbitrary sensitive error messages/extension redaction and real request observer behavior.
- API research and Belgian variable-MODEL economics are documented in `docs/engineering/BE_GRAPHQL_API_RESEARCH.md` and the HA Energy Basic source contract. A monthly variably settled rate and market spot signal are **different** facts. No financial-arbitrage claim for an unverified variable tariff.

## Baseline observed on real BE account, version 2026.11.1.7

- On 2026-11-01 around 14:08 Brussels, today selected customer electricity and gas price series each contained 24 hourly slots. Tomorrow had 24 electricity hours and **six** gas hours, so tomorrow gas daily aggregates must be considered partial.
- `MonthInsights(2026-11)` returned GraphQL errors and `monthInsights:null`; this prerelease can identify a safe cause category in the next export but **does not fix the provider error**.
- `MonthInsights(2026-10)` explicitly excludes gas despite some expected-gas fields; `PeriodUsageAndCosts` has no observed prior-day gas segment. The selected site reports variable MODEL, electricity SMR3, gas SMR1 and missing recent gas reading. These are facts to reconcile with supplier app/contract, not values to invent.
- Optional `SmartHvacStatus` API exception is non-blocking; Enode and PV lists genuinely empty for this account.
